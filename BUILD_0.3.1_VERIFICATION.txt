# Egorov OS 0.3.1 — Сборка 6: «в логе пишем обо всём» + #495/#496/#497/#498

Версия продукта: 0.3.1. Номер сборки: 6.

## Состав

- #494 МЕГА-ЛОГ (kernel/usbdump.c): PCI-дамп всех устройств с именами
  (выжимка pci.ids), полные USB-дескрипторы (device/config/HID/EP),
  СТРОКИ устройств (производитель/продукт/серийник, UTF-16LE→UTF-8),
  побитовая расшифровка PORTSC/USBCMD/USBSTS, метки времени TS=Nс.
  Пути: xHCI + EHCI + OHCI.
- #495 (КРИТИЧЕСКИЙ) EHCI: квитанция IAA (R/WC) до звона doorbell и
  внутри ожидания — неподтверждённый IAA паркует обход async-кольца
  (EHCI 1.0 §4.8.5), qH никогда не исполняется. Снимает вечные
  «GET_DESCRIPTOR не прошёл» на реальном AMD (IAA=1+IAAD=1 в дампах
  Сборки 5) и флэк e2e T2/T4/T18 в QEMU (~40%).
- #498 (КРИТИЧЕСКИЙ) OHCI: кодировка тогглов TD возвращена к канону
  Linux ohci.h: DATA0=0x02000000 (10b), DATA1=0x03000000 (11b),
  carry=0. Пара 01/10 (0.3.1) была обратной: SETUP с Зарезервированным
  01b, DATA/STATUS с DATA0 вместо DATA1 — на реальном железе устройство
  ACKает SETUP и игнорирует IN со сбитым тогглом -> cc=5 навсегда
  («чёрные гнёзда» EGOROV.LOG Сборки 5, OHCI#2 порты 4/5). QEMU
  контрольные тогглы не моделирует — ловится статикой.
- #496: wValue строковых запросов (0x03<<8)|index во всех трёх путях
  (было (index<<8)|0x03 — устройство получало «DEVICE №3» вместо STRING).
- #497: FIT-переключение при записи HcFmInterval (Linux parity) +
  декодер USBSTS по битам спеки (HALT=12, RECL=13, PSS=14, ASS=15).

## Ожидания от реальной загрузки (следующий EGOROV.LOG)

1. PCI-DUMP: все контроллеры по именам (эквивалент lspci).
2. USB-STR: имена клавиатуры/мыши/флешки (как lsusb).
3. OHCI «чёрные гнёзда»: первые ДЕСКРИПТОРЫ вместо вечного cc=5 (#498);
   если cc=5 остался — дампы теперь честные (декодер по битам спеки).
4. EHCI: таймауты без «IAA=1 HALT=1» и с честным ASS (#495, декодер).
5. TS=Nс у ключевых событий — видно, ГДЕ именно всё стопорится.

## Известные ограничения

- #495/#498 не моделируются QEMU: реальное поведение подтверждается
  только загрузкой Сборки 6 на целевой машине.
- Списки имён (pci.ids-выжимка) — только для журнала; драйверы, как и
  в Linux, привязываются по классу/интерфейсу, «списка устройств» нет.
